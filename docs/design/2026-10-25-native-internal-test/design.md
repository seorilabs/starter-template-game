# 공개 게임 템플릿의 네이티브 빌드와 내부 테스트

사용자는 저장소 공개, Android와 iOS 실제 서명 빌드, Google Play 내부 테스트와 TestFlight 내부 배포를 요청했다. 이어 앱 이름 Seorilabs Game Starter, 식별자 com.seorilabs.startergame과 첫 버전 v1.0.0을 선택했다. 이 대화가 기존 release: null의 범위를 두 마켓의 test-track까지 확장한 승인 근거다. 공개 전 전체 Git 이력의 비밀값 검사는 통과했고 저장소는 공개로 전환했다.

## 범위와 흐름
기존 로컬 게임의 시작, 체험, 별 수집, 결과와 저장 흐름을 유지한다. 실행 화면의 이름은 선택한 앱 이름을 사용한다. 게임이나 공통 묶음의 구조와 외형은 개편하지 않는다. 새 SDK, 서버, 결제 상품과 운영 계정 연결은 추가하지 않는다. 기기나 시뮬레이터는 사용하지 않는다. 네이티브 설치와 실제 하드웨어 동작은 이번 근거로 주장하지 않는다.

명시적 v1.0.0 태그와 중앙 원장 영수증이 두 플랫폼의 버전을 정한다. Android는 서명 AAB를 만들고 internal 트랙 completed와 테스터 참여 경로를 확인한다. iOS는 App Store 배포 서명으로 archive와 IPA를 만들고 처리 VALID, 내부 그룹의 빌드 연결과 사용 가능한 테스터를 확인한다. 심사 제출, 외부 테스트와 공개 출시에는 진행하지 않는다.

## 구현과 책임
기존 중앙 재사용 workflow를 얇은 caller로 호출한다. Android는 GitHub-hosted Linux, 공개 저장소 iOS는 GitHub-hosted macOS를 사용한다. main과 PR은 검사만 실행한다. 초기화 원장을 먼저 도입하여 최초 마켓 설정 전에 검증된 미출시 상태를 0 기준으로 기록하고, 다음 변경에서 실제 내보내기와 마켓 설정을 추가한다. 키는 공통 배포 identity를 재사용하고 누락된 앱 전용 Android 키와 iOS profile만 등록한다. 비밀값은 공개 저장소에 넣지 않고 카탈로그와 GitHub environment에 둔다. 백업과 양쪽 복원 검증을 통과한 뒤 자격증명을 변경한다.

Android와 iOS 내보내기는 같은 로컬 게임을 사용하며 tests와 서비스 대역을 제외한다. fonts의 OFL과 SDK LICENSE를 포함한다. 내부 테스트용 앱의 식별자와 서명은 복제한 새 제품에 재사용하지 않는다. 제품 초기화와 마켓 설정을 별도 명령으로 명시하고, 새 제품은 자체 식별자와 서명, 등록 정보를 사용한다.

## 검수와 실패 처리
L3 개발 환경 전체 회귀를 동일 후보의 CI에서 실행한다. 기존 13개 기능의 입력과 저장 복원, 공통 87개 계약, 새 네이티브 설정 검사와 actionlint를 유지한다. 이름 변경은 작은 화면의 기존 입력 여정을 실제 렌더로 확인한다. 실제 서명 산출물의 앱 이름, 패키지, 버전, 서명과 포함 파일을 읽는다. 빌드, 업로드, 처리와 테스트 도달은 각각 기록한다. 콘솔 계정, 권한, 서명 또는 중앙 검증이 막히면 다른 계정이나 키로 우회하지 않고 해당 마켓의 blocker를 보존한다. 다른 마켓과 개발 환경의 작업은 계속한다.

## 운영과 복구
업로드는 명시적 dispatch만 수행하고 production 트랙과 심사 제출을 제공하지 않는다. 실패한 태그를 이동하거나 이미 쓴 빌드 번호를 재사용하지 않는다. 추가 버전이 필요하면 사용자가 선택한 버전 범위를 확인한다. 키를 회전하거나 사용자 저장을 삭제하지 않는다. 산출물과 검수 원본은 NAS에 직접 읽기 해시 검증 후 이관하고, 작업 worktree와 재생성 캐시는 정리한다.
